# AI Account Switcher MVP Implementation Plan
Status: Approved 2026-10-16

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `ais`, a macOS CLI (plus optional SwiftBar menu) that resumes the same Claude Code session on another signed-in account with one command.

**Architecture:** One Python zipapp. `cli.py` parses and maps exit codes; `core.py` holds the commands and owns the cache; `store.py`, `guards.py`, `accounts.py`, `runner.py` and `menu.py` are the cross-cutting parts; everything Claude-specific (environment, billing risks, transcript layout, snapshot paths, constants) lives in `providers/claude.py` behind a `typing.Protocol`. ais never writes to `~/.claude`, `~/.claude.json`, `~/.claude-accounts/` or the Keychain.

**Tech Stack:** Python 3.9+ standard library only; `unittest`; GitHub Actions; SwiftBar (optional, user-installed).

**Spec:** `docs/superpowers/specs/2026-10-16-ai-account-switcher-design.md`, `docs/requirements.md` (v0.4), `docs/architecture.md`, `docs/adr/0001` to `0008`; Desktop per account: `docs/superpowers/specs/2026-10-16-ais-desktop-design.md` (approved 2026-10-16, FR-6). Where the design spec says `--continue`, ADR-0006 wins: always `claude --resume <id>`.

## Global Constraints
- Python 3.9 syntax (use `Optional`, `List`, `Dict` from `typing`); standard library only (ADR-0001).
- Exit codes: 0 ok; 64 bad input; 65 declined; 66 nothing to resume / not found; 69 `claude` not found; 71 SwiftBar missing; 73 cannot write; 75 session open; 77 billing guard; 78 config error; otherwise `claude`'s own code, or 128+N if `claude` died from signal N.
- `CLAUDE_SECURESTORAGE_CONFIG_DIR` omitted entirely for the default account, never ""; credDir passed exactly as stored; `CLAUDE_CONFIG_DIR` never set.
- Never call `security` with `-w` or `-g`.
- Files 0600, directories 0700 under `~/.config/ais/`; every read-modify-write and log rotation under `fcntl.flock` on `~/.config/ais/.lock`, never held while waiting for input.
- Account ids `^[a-z][a-z0-9-]{0,31}$`; session IDs are UUIDs.
- Every subprocess call has an explicit `timeout=`.
- Tests set `HOME` to a temp dir and put fake `claude`, `security`, `pgrep`, `lsof`, `cp`, `ps`, `open` first on `PATH` (`tests/fakes/`); settings roots and app roots are injected, never the host's `/Library` or `/Applications`.
- No FR task (task 3 onward) starts before task 2's gates pass.

## Review Focus
1. **Folder paths with spaces, unicode (NFD from Finder) or symlinks** (`~/Dev/My Project`, `~/Café`): switch must still find the session and resume in the right folder. Test in task 7 (`test_newest_session_unicode_space_and_symlink_folder`).
2. **The limited session is still open in the same folder**: `ais switch` must refuse (75) with the `/exit` hint, and the menu must show the disabled "Quit Claude in <folder> to resume". Tests in task 14 (`test_open_session_75_with_exit_hint`) and task 18 (`test_open_session_shows_disabled_quit_item`).
3. **The other account is also at its limit or logged out**: ais must still start `claude` (Claude Code's own login or limit message appears; G-1(c) records which) and pass its exit code through. Test in task 11 (`test_child_exit_code_and_signal_passthrough`).
4. **Config hand-edited badly** (trailing slash, `~` in credDir, unknown provider, unknown version, JSON syntax error): clear message, exit 78, never a traceback. Test in task 4 (`test_config_errors_exit_78`).
5. **SwiftBar running with a minimal PATH, no TTY and a hung tool**: `ais menu render` must never prompt, never hang past 5 s, and leave no child behind. Test in task 18 (`test_render_with_hung_lsof_finishes_in_5s`).
6. **The Work Desktop is already open** (clicked twice in the menu, or run twice): `ais desktop work` must not start a second instance on the same data folder (the spike showed Claude.app allows it). Test in task 17b (`test_already_running_does_not_launch`).
